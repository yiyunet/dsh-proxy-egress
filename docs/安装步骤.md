# 安装与接线

> 目标：让消费方填 `http://127.0.0.1:8899` 就能用，账号密码只在上游那一跳出现一次。

---

## 前置

- Node ≥ 22.19
- 已有一个可用的 DSH profile

---

## 步骤 0 · 先跑离线验证

```sh
npm test           # 纯逻辑 + 沙箱里真跑客户端面板
npm run smoke      # 离线端到端（假上游 + 假目标）
npm run faultcheck # 证明上游坏掉时不会直连
```

三项全绿再往下走。**不绿就别接线** —— 接了也定位不到是哪一层的问题。

---

## 步骤 1 · 准备凭据文件

凭据放在**插件目录之外**的一个独立文件里，不写进任何配置：

```json
{ "username": "<上游代理账号>", "password": "<上游代理密码>" }
```

Windows PowerShell 下建议这样写，避免手写 JSON 被特殊字符搞坏、也避免 BOM：

```powershell
New-Item -ItemType Directory -Force -Path D:\keys | Out-Null
$json = @{ username = '<账号>'; password = '<密码>' } | ConvertTo-Json -Compress
[System.IO.File]::WriteAllText('D:\keys\proxy-egress.json', $json, (New-Object System.Text.UTF8Encoding($false)))
```

> 插件会剥掉 UTF-8 BOM，但那只是兜底，不要依赖它。

---

## 步骤 2 · profile 的 `package.json`

`<PROFILE_DIR>` 指 `$DSH_HOME/profiles/<profile 名>`（Windows 下形如
`C:\Users\<你的用户名>\.dsh\profiles\web`）。

`dependencies` 加一条（用 `link:` 指向本仓库目录，便于改代码即热重载）：

```json
"@yiyunet/dsh-proxy-egress": "link:<本仓库绝对路径>",
```

`dsh.profile.bundles` 加一项：

```json
"@yiyunet/dsh-proxy-egress",
```

---

## 步骤 3 · profile 的 `cordis.patch.yml`

先备份这个文件。它是**宿主启动配置**，写坏会导致宿主起不来。

### 3a · 配置本插件

```yaml
- id: proxy-egress
  config:
    listen:
      host: '127.0.0.1'
      port: 8899
    upstream:
      type: 'http'            # 上游是 HTTPS 入口时改 'https'
      host: '<上游代理主机>'   # 只写主机名/IP，端口另写
      port: 8080
    credentialSource: 'file'
    credentialFile: '<凭据文件绝对路径>'
    allowConnectPorts: [443]
    expectedEgressIps: []     # 填上即启用"出口钉定"
    egressMismatchAction: 'warn'
    selfCheck:
      enabled: true
      url: 'https://api.ipify.org?format=json'
```

> ⚠️ **必须用「同 id 顶层覆盖」，不能写成 `- insert:`。**
> 本包自带的 patch 已经插入了 `proxy-egress` 这一行；再 `insert` 一次会变成
> **两个同 id 的行**，两个实例抢同一个端口。症状是 `EADDRINUSE`，很容易被误判成
> "端口被别的程序占了"。
> 判据：`dump-config` 里应出现
> `# == @yiyunet/dsh-proxy-egress, patched by ...cordis.patch.yml`。

### 3b · 把消费方指过来

```yaml
- id: <你的消费方行 id>
  name: dsh-codex-connect
  config:
    enableProxy: true
    proxyUrl: 'http://127.0.0.1:8899'   # 无凭据
    imageGenerationModel: gpt-image-2.5
```

> **`config` 是整体替换，不是合并** —— 非代理字段（如 `imageGenerationModel`）
> 要一并写上，否则会丢。
>
> 建议分两次改：先只改 `name` / 字段名，把消费方恢复可用；确认代理 `listening`
> 之后再把 `enableProxy` 改成 `true`。**一次只动一个变量**，出问题才分得清是
> 包名不对还是链路不对。

## 步骤 3.5 · 安装符号链接

`bundles` 是手改的，但符号链接必须装出来，否则加载器解析不到包：

```sh
dsh plugin --profile <profile> install
```

---

## 步骤 3.6 · 重启前的 10 秒预检

```sh
dsh --profile <profile> --dump-config
```

确认两件事：

1. 只有**一行** `proxy-egress`，且带 `patched by ...cordis.patch.yml`
2. 消费方的 `name` 是真实包名（不是已卸载的旧包）

这一步能验证 YAML 语法 + 包解析，**不用等重启**发现。

---

## 步骤 4 · 重启并自检

| 工具 | 期望 |
|---|---|
| `proxy_egress_status` | `state: listening`、`credential.fingerprint` 有值 |
| `proxy_egress_faultcheck` | `baitConnections: 0` |
| `proxy_egress_selfcheck` | `result: OK` + 一条 `observedEgressIp` |

把 `observedEgressIp` 填进 `expectedEgressIps`，从 `warn` 起步；稳定后再考虑 `block`。

也可以直接在 **设置 → 出口代理** 面板里做同样的事。

---

## 步骤 5 · 真实消费方验收（人工，绕不过去）

让消费方发一次**可识别的新请求**（别用缓存结果），然后确认：

1. 请求成功；
2. `proxy_egress_status` 里的 `stats.connectEstablished` 增长了 —— 证明消费方**真的**走了代理；
3. 把上游停掉再发一次 —— 应当是**失败**，且没有到目标的连接尝试。

第 3 条是判断"有没有偷偷直连"的唯一办法：**看行为，不看业务是否成功**
（业务失败也可能是直连也失败）。

---

## 回滚

1. 从 `bundles` 删掉本插件那两项（`package.json` 与 `cordis.patch.yml`）；
2. 把消费方的 `enableProxy` 改回 `false`（或改回它原本的路径）；
3. 重启宿主。

插件卸载时会释放端口与全部连接，不留残留。

## 实机踩坑记录

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | `dump-config` 里出现**两个** `proxy-egress` 行 | profile patch 用了 `- insert:`；包自带 patch 已插入过该行，再 insert 就是新增第二行 → 两个实例抢同一端口 | 改成**同 id 顶层覆盖** |
| 2 | 自检 `result` 说 `UPSTREAM_UNREACHABLE`，`detail` 却说 `UPSTREAM_REJECTED` | 分类映射用 `?:` 链兜底，未列举的原因码被吞成"不可达" | **原样透传**原因码 + 新增 `X-Egress-Upstream-Status` 响应头 |
| 3 | 上游对错误凭据返回 **401**（不是标准 407） | 各家代理实现不一致 | 401 与 407 一并归入 `UPSTREAM_AUTH_FAILED`，并带出状态码 |
| 4 | 控制台显示 `浣犵殑瀵嗙爜` 这类乱码 | PowerShell 控制台代码页，不是文件问题 | 无需处理；另已兼容 UTF-8 BOM |
| 5 | 打开面板后页面卡死 | `useCallback` 依赖 `props.rpc`，而 `inject()` 每次渲染给新函数引用 → `useEffect` 每次重跑 → 无限渲染 | 用 `ref` 固定 `rpc`，让依赖真正为空 |
| 6 | 设置面板"改了没生效" | 槽位 id 与包名是两件不同的事（前者短名、后者说明符），混用会**静默失败** | 两者分开断言 + `notEqual` 保护 |
| 7 | 面板改动保存后需要能看清"这个值从哪来" | 面板覆盖与装载行配置并存，两个来源打架时不可见 | 状态里输出 `overrides.origins`，面板标注"面板/配置文件" |
