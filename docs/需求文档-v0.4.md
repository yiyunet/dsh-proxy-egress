## 0. 本版改了什么

### 0.1 四条硬错误（已修）

| 编号 | v0.3 的错误 | 本版 |
|---|---|---|
| **E1** | FR-12 用「最近获得 <500 响应」当成功判据 | **删除**。CONNECT 隧道内是 TLS，本插件只搬运字节，**看不到目标 HTTP 状态码**。改为四层可观测状态（§7） |
| **E2** | 把 `defineTool` 注册的模型工具当成终端命令（`egress status`）；`config` 工具带 `password` 参数 | **拆开**：工具只做状态/验证/重启，**永不接收或回显凭据**（§4.7）。终端命令若需要，另做 CLI，与工具不是一回事 |
| **E3** | 把 hosts 黑洞定性为「唯一绝对保证」 | **降级**为「指定域名的辅助防误连，不可证明强制出口」（§2.3） |
| **E4** | 隧道已建立后仍向客户端写 502 | **按阶段分治**：发 200 之前可回代理错误；发 200 之后**只关闭隧道并记录**，绝不再写 HTTP 字节（§4.3） |

### 0.2 八项审查意见的处理

| 审查意见 | 处理 |
|---|---|
| T1/T2/T3 一视同仁不成立 | 采纳。改为**接入兼容表**，并补一条更强的事实：Node 原生 `fetch`（undici）**默认不读** `HTTP_PROXY`/`HTTPS_PROXY` |
| hosts 越权承诺 | 采纳。L3 拆两档：hosts 不可证明 / 防火墙白名单需单独设计并验收 |
| 自检容易误判 | 采纳。三分法 + 分类结果码 + 死端口法改用**独立实例**；判据从「请求失败」改为「**是否存在绕过代理的连接尝试**」 |
| 固定出口缺执行机制 | 采纳。新增 `expectedEgressIps` / `lastObservedEgressIp` / `lastVerifiedAt` / `egressMismatchAction` |
| 凭据保护 | 采纳。工具零凭据通道、A→B 迁移、HTTP 上游 Basic 明文风险、HTTPS 上游提 P0 |
| CONNECT 与普通 HTTP 必须分开 | 采纳。§4.3 / §4.4 分成两份规范 |
| 自检失败停监听没用 | 采纳。改为**保留监听、拒绝新请求**的阻断态；自检分类；生命周期补齐 |
| 状态与里程碑冲突 | 采纳。6 处冲突逐条消除（§9） |

### 0.3 保留的异议（不改）

1. **范围要窄**：接入兼容表只对**一个真实消费方**做实测，其余标「未验证」。不为了填表去适配假设场景。
2. **HTTP 上游不禁止**：只做分级与告知。大量账密代理只给明文 HTTP 端口，一刀切会让用户直接卡住。

## 1. 背景与目标（抽象化）

有一类**模型供应商接入插件**，它们把代理能力暴露成一个配置项，语义统一是：

> 「一个 **不含账号密码** 的 HTTP(S) 代理地址」

原因是这类字段会被写进 profile 配置、被设置面板回显、被日志与诊断带出。所以它们会显式拒绝带凭据的值（本机实测见 §3）。

而真实的上游代理基本是「`账号:密码@IP:端口`」。

**裂口就在这里**：一边只能给裸地址，一边必须带凭据。

### 1.1 目标

在本机回环上开一个**无需认证的转发代理**，由它向上游注入凭据：

```
消费方 ──► 127.0.0.1:8899（无认证）──► 注入 Proxy-Authorization ──► 上游 ──► 目标
```

### 1.2 成功标准

| 编号 | 标准 |
|---|---|
| S1 | 消费方的代理字段填 `http://127.0.0.1:8899` 即可用，**消费方侧看不到账号密码** |
| S2 | 上游不通时**零直连**，且有可复现的证据 |
| S3 | 能答出「现在的出口 IP 是多少、和期望是否一致」 |
| S4 | 凭据不进入对话记录、工具调用日志、宿主审计 |

## 2. 边界（本版最重要的一节）

### 2.1 NFR-7 正式表述

> **本插件保证**：进入本地代理的数据连接，只能通过所配置的上游代理转发；上游失败时**不创建到目标的直连连接**。
>
> **本插件不保证**：强制出口管控。对消费方绕过代理的行为，本插件**不具备阻断能力**。
>
> 若需要可证明的强制出口约束，必须结合系统网络隔离，并**单独验收**。
>
> **MVP 交付范围：仅保证 L1；系统级强制出口尚未验收。**

### 2.2 三层责任

| 层 | 内容 | 可证明性 | 归属 |
|---|---|---|---|
| **L1** | 进入本监听的连接只走上游；失败不直连 | **代码级，可测** | 本插件 |
| **L2** | 消费方是否把请求交给本监听、失败后是否自行 fallback | **不可控**，只能取证 | 消费方 |
| **L3** | 整机出口约束 | 见 §2.3 | 系统 |

### 2.3 L3 两档（不再混为一谈）

| 手段 | 效力 | 结论 |
|---|---|---|
| hosts 黑洞 | **只改名称解析**。管不住：直连 IP、已建立连接、应用自带解析、新增/备用域名、本地端口恰好有监听 | **辅助防误连措施，不可证明强制出口** |
| 防火墙白名单 / 独立网络环境 | 按远端地址+端口限制宿主整体出口 | **在明确范围与测试条件下可证明**，但需单独设计允许范围并验收 |

两条必须记住的事实：

1. **Windows 显式阻止规则优先于冲突的允许规则**，所以「先全阻止再放行代理」是错的，必须逐条白名单设计。
2. v0.3 说「程序级防火墙不可行，因为插件与宿主同进程」——**这个理由不成立**。同进程照样能按远端地址/端口/协议限制宿主出口，代价是会影响宿主其它网络功能，需要完整允许范围设计。

### 2.4 接入兼容表

本插件只能帮到**接受代理地址**的消费方。**不存在「一视同仁」。**

| 类 | 消费方形态 | 能否接 | 前提 |
|---|---|---|---|
| **T1** | 有代理配置项（字段名各异） | **能** | 该字段接受无凭据 HTTP 地址 |
| **T2** | 无代理字段，但走 Node 网络库 | **需实测** | 见下方警告 |
| **T3** | 自带网络栈 / 子进程 / 原生二进制 | **基本不能** | 只能靠 L3 系统隔离 |

> ⚠️ **T2 的关键事实**：Node 原生 `fetch`（undici）**默认不读** `HTTP_PROXY`/`HTTPS_PROXY`，需要显式 `EnvHttpProxyAgent` 或 `setGlobalDispatcher`。所以「设环境变量就生效」不成立。
>
> ⚠️ **`NO_PROXY` 会改变路由**，本插件无法覆盖。
>
> ⚠️ **字段名不可泛化**：`enableProxy` / `proxyUrl` 只是**某类消费方的示例字段**，不是通用语义。

### 2.5 实测矩阵（只有一行是真的）

| 宿主版本 | Node/Electron | 消费方版本 | 网络库 | 接入方式 | 实测结果 |
|---|---|---|---|---|---|
| 本机 web profile（2026-10-12） | Node ≥22.19 | `dsh-codex-connect@0.2.0-alpha.10` | undici `ProxyAgent` | `enableProxy:true` + `proxyUrl: http://127.0.0.1:8899` | **代理层已实测通过**：selfcheck `OK`、观测出口 `<上游出口 IP>`、与 `expectedEgressIps` 一致（`matched:true`）、faultcheck 诱饵连接 `0`。**消费方真实请求是否经代理：待验（A13）** |

其余行一律「未验证」。**不填不写。**

## 3. 已确认的事实基线

以下为本机实读，可复核：

| 事实 | 位置 |
|---|---|
| 消费方要求代理地址**不带凭据**，否则抛错 | `dsh-codex-connect/lib/index.js:3023` — `throw new TypeError("OpenAI Codex proxyUrl must be an HTTP(S) origin without credentials or a path")` |
| 该插件用 undici `ProxyAgent` 走代理 | 同文件 `5342-5360`、`6806`（`new ProxyAgent(proxyUrl)`） |
| 该插件声明「代理请求失败时绝不静默改走直连」 | `docs/reference.zh.md` |
| `ctx.effect(execute)` 立即执行、返回的 disposer 在卸载时执行，且支持返回 Promise | `deepseek-harness/vendor/cordis/src/fiber.ts:415-418` |
| 宿主插件导出形如 `export function apply(ctx, config)` + 可选 `export const inject` / `Config` | `cordis-plugin-development/references/host-plugin.md` |
| `@deepseek-ai/dsh-tools` 等运行时包由宿主解析，**不得写进任何依赖节** | 同类 DSH 插件的 `plugin-src/host/index.mjs:21-28` |

### 3.1 顺带查出的一处本机配置问题

profile 的 `cordis.patch.yml` 里 `llm-openai-codex` 这一行目前是：

```yaml
- id: llm-openai-codex
  name: dsh-codex            # ← ①
  config:
    proxyMode: scoped        # ← ②
    proxyUrl: http://<账号>:<密码>@<IP>:<端口>   # ← ③（此处不复述凭据）
```

三处都与本机实际不符：

| # | 问题 | 状态 |
|---|---|---|
| ① | `dsh-codex` 这个包**已被卸载**，profile `node_modules` 里只有 `dsh-codex-connect` | **已确认（老板告知）**：该行指向不存在的包，必然加载失败 |
| ② | `proxyMode` 不是该插件的配置字段（插件字段是 `enableProxy`）；`proxyMode` 只是设置页里的前端局部状态名 | 已确认（`lib/client.js:1180` 是 React 局部 state） |
| ③ | `proxyUrl` 带凭据，触发 `index.js:3023` 的类型错误 | 已确认（`normalizeOpenAICodexProxyUrl` 在 `username`/`password` 非空时返回 `undefined`） |

**结论**：ChatGPT 订阅模型当前**不可用**。修复不是"调一下参数"，而是把 `name` 改回真实包名，并把凭据搬进本插件的凭据文件。

### 3.1.1 消费方字段契约（已查实）

`normalizeOpenAICodexProxyUrl`（`lib/index.js:2941-2953`）逐条判定：

| 条件 | `http://127.0.0.1:8899` |
|---|---|
| 协议是 `http:` / `https:` | ✅ |
| `username` 与 `password` 均为空 | ✅ |
| `pathname === '/'`（不含路径） | ✅（无尾斜杠时 URL 解析结果即为 `/`） |
| `search` 与 `hash` 为空 | ✅ |
| 端口 1–65535 | ✅ |

返回 `parsed.origin`，所以消费方侧 `http://127.0.0.1:8899` 与带尾斜杠的写法等价，**不需要**尾斜杠。

## 4. 功能需求

### 4.1 FR-1 本地监听

| 项 | 要求 |
|---|---|
| 绑定 | **只允许回环**（`127.0.0.1` / `::1`）。写别的直接拒绝启动 |
| 默认端口 | web 8899 / desktop 8990 |
| 端口冲突 | **不自增、不换端口**，直接报错。换端口会让消费方悄悄连到别的服务 |
| 认证 | 本地监听**不做认证**（依赖回环绑定） |

### 4.2 FR-2 上游连接

| 项 | 要求 |
|---|---|
| 协议 | P0：`http` / `https`（TLS 到代理）。`socks5` 未实现，配置里写了**明确报错** |
| 认证 | Basic（`Proxy-Authorization`），仅在上游这一跳注入 |
| 超时 | 拨号、握手、响应头各有上限 |
| 直连 | **不存在这条路径** |

### 4.3 FR-3 CONNECT 隧道（严格分阶段）

| 阶段 | 要求 |
|---|---|
| 目标解析 | IPv4 / **带方括号的 IPv6** / 域名 **三分法**。禁止「含冒号就是端口」 |
| 端口白名单 | 必须配置，默认 `[443]`。空数组 = 配置非法。**否则本插件就是开放 TCP 转发器** |
| 成功判定 | 必须解析**完整合法状态行**并落到 2xx。见 `\r\n\r\n` 就当成功是错的 |
| 粘包/拆包 | 处理客户端 `head`，以及上游响应头后**同包到达**的隧道数据 |
| 上限 | 响应头最大字节数 + 握手超时 |
| 状态码 | 2xx → 成功；407 → `UPSTREAM_AUTH_FAILED`；其他 → `UPSTREAM_REJECTED`；解析失败 → `UPSTREAM_MALFORMED_RESPONSE` |
| **发生 200 之后** | 任何错误**只能关闭隧道并记录**。再写 HTTP 响应会污染 TLS 流 |
| 凭据外泄 | `Proxy-Authorization` 属逐跳头，**绝不转发给目标** |

### 4.4 FR-4 普通 HTTP 转发

| 项 | 要求 |
|---|---|
| 请求形式 | 只接受**绝对形式**（`GET http://host/path`）；origin 形式回 400 |
| 状态码 | **目标业务状态码原样透传**（401/429/500 都是正常业务响应，不得改成 502） |
| 逐跳头 | `Connection`/`Keep-Alive`/`Proxy-*`/`TE`/`Trailer`/`Transfer-Encoding`/`Upgrade` 按规范剥离 |
| 认证头 | 消费方的本地认证与上游认证**严格分离**；消费方传来的 `Proxy-Authorization` 一律丢弃后重写 |
| 长连接 | 背压、客户端取消、对端关闭、长 SSE |
| 错误分阶段 | 未发响应头 → 可回 502；已发 → 只能 destroy |
| Upgrade | 501（不做，且要明确拒绝） |

### 4.5 FR-5 失败即断联（不可协商）

| 项 | 要求 |
|---|---|
| 直连降级 | **不存在**。配置里写 `allowDirectFallback` / `fallbackDirect` / `directFallback` / `retryDirect` 一律**报错**，不静默忽略 |
| 重试语义 | 禁止的是**直连目标重试**；经同一上游重试另定规则 |
| 失败返回 | 分类原因 + `X-Egress-Reason` 响应头 |

### 4.6 FR-6 阻断态

| 项 | 要求 |
|---|---|
| 形态 | **保留监听、拒绝新请求**（不是停监听）。停监听会让恢复需要重新 listen、状态也不可观测 |
| 触发 | `egressMismatchAction=block` 且观测出口不匹配；管理员手动 |
| 已建立隧道 | **不中断**（隧道内字节已无边界，中途掐断会毁掉进行中的模型调用）。此缺口必须写在文档里 |
| 恢复 | 重新自检通过 + 显式操作 |

### 4.7 FR-7 凭据（修 E2）

| 通道 | 能力 | 禁止 |
|---|---|---|
| **A · 模型工具** | `status` / `selfcheck` / `faultcheck` / `restart` | **禁止接收或回显密码**；状态只回 `credentialConfigured: true/false` + 指纹 |
| **B · 装载行 config** | `username` / `password` 明文进 profile patch | —— |
| **C · 独立凭据文件**（推荐） | 只写文件绝对路径 | 文件内容不进任何日志 |

补充两条：

- `ctx.tools.register` 注册的是**模型可调用工具，不是 shell 命令**。若需要 `egress status` 这类终端入口，必须另做 CLI。
- 运行时表述改为：**转发时认证头仅在内存构造；原始凭据按所选存储模式保存**（消除与 v0.3 FR-10A 的冲突）。
- 模式 C 的定位：**外置保存，减少凭据进入 profile 与配置导出的机会**，**不构成同进程隔离**。
- A→C 迁移：必须删除 profile patch 里的明文，并清理 `.bak` 等历史备份，否则 A7 永远不过。

### 4.8 FR-8 自检三分法

| 检查 | 做法 | 输出 |
|---|---|---|
| **代理链路** | 经正式转发路径访问回显服务 | 观测出口 IP + 比对结果 |
| **故障注入** | **独立实例 + 诱饵端口**（不动生产配置） | 诱饵连接数必须为 0 |
| **消费方接入** | 让真实消费方发一次**可识别的新请求** | 是否存在**绕过代理的连接尝试**（不是业务成败） |

分类结果码：

`OK` / `UPSTREAM_UNREACHABLE` / `UPSTREAM_AUTH_FAILED` / `UPSTREAM_REJECTED` / `TARGET_UNREACHABLE` / `EGRESS_IP_MISMATCH` / `CHECK_SERVICE_UNAVAILABLE` / `LISTENER_DOWN` / `CONNECT_PORT_NOT_ALLOWED` / `PROXY_BLOCKED`

原则：**自检失败 ≠ 模型链路失败**。回显服务挂了只是 `CHECK_SERVICE_UNAVAILABLE`。

### 4.9 FR-9 出口 IP 钉定

| 字段 | 说明 |
|---|---|
| `expectedEgressIps` | 期望出口列表；空 = 只报告不比对 |
| `lastObservedEgressIp` / `lastVerifiedAt` | 最近一次观测 |
| `verificationConfigVersion` | 配置一变，旧结果作废（V5） |
| `egressMismatchAction` | `warn` / `block` |

**必须写在产品说明里**：「专属、固定」最终取决于**上游代理服务自身**的能力与契约（粘性会话 / 独占端口 / 住宅 vs 机房）。本插件只能「验证并约束已观测出口」。

### 4.10 FR-10 生命周期

| 项 | 要求 |
|---|---|
| socket 登记表 | client / upstream / 握手中，分阶段计数 |
| 清理 | `closeAllConnections()` **不销毁** upgrade/connect 出来的 socket → 必须先按登记表销毁 |
| 配置快照 | 不可变 + 版本号，避免握手中途换到另一套凭据 |
| 串行化 | `start` / `stop` / `restart` 进同一队列 |
| 启动失败 | `void controller.start()` 的 rejection **必须被处理**，落到状态系统，不得掀掉宿主 |
| 卸载 | 端口释放、连接归零 |

### 4.11 FR-11 传输安全分级

| 上游位置 | 结论 |
|---|---|
| 同机 / 同内网可信网段 | HTTP 上游可接受 |
| **跨公网** | **优先 `https` 上游**。HTTP 上游时 Basic 只是 Base64（RFC 7617），账号密码在链路上**可被还原** |
| SOCKS5 | 用户名密码**同样不自带加密** |

不禁止 HTTP 上游，但必须在配置校验时给出警告与后果说明。

### 4.12 FR-12 可观测状态（修 E1）

| 状态 | 插件能证明什么 |
|---|---|
| 本地监听正常 | 端口正在接受连接 |
| 上游隧道建立成功 | 上游接受了 CONNECT |
| 隧道已有双向数据 | 发生过实际转发 |
| 自检通过 | 指定目标在指定时间通过 |
| **消费方业务成功** | **需要消费方反馈或外部验收，插件不能自行判断** |

**删除**「获 <500 响应」这一判据。

### 4.13 FR-13 消费方接入方式（修）

| 方式 | 可靠性 |
|---|---|
| 消费方配置项填 `http://127.0.0.1:8899` | **首选**，唯一可靠 |
| 环境变量 `HTTP_PROXY`/`HTTPS_PROXY` | **不可靠**：Node 原生 fetch 默认不读；`NO_PROXY` 会改路由 |
| 系统代理 | 仅对读系统代理的进程有效，且影响面大 |

### 4.14 FR-14 发布形态

| 项 | 要求 |
|---|---|
| 形态 | DSH bundle，`package.json` 声明 `dsh.bundle.patch` |
| 构建 | **零构建**：`plugin-src/` 即真源，`exports` 直指 `.mjs` |
| 依赖 | 零运行时依赖。`@deepseek-ai/dsh-tools` 由宿主解析，**不得写进依赖节** |
| 分发 | `lib/` 不入库；如果将来引入构建，**发布包必须含构建产物，并验证安装后可加载** |

## 7. 验收标准

### 7.1 代理层（可自动化）

| 编号 | 判据 | 命令 |
|---|---|---|
| A1 | 正常隧道建立、认证头由本插件注入 | `node scripts/smoke.mjs` |
| A2 | 上游 407 → `UPSTREAM_AUTH_FAILED` 且**目标零连接** | 同上 |
| A3 | 上游不可达 → `UPSTREAM_UNREACHABLE` 且**目标零连接** | 同上 |
| A4 | 非白名单端口 → 403 | 同上 |
| A5 | 普通 HTTP 走绝对形式、业务状态码透传 | 同上 |
| A6 | 停止后端口释放 | 同上 |
| A7 | 故障注入：诱饵端口零连接 | `node scripts/faultcheck.mjs` |

### 7.2 宿主集成（需真实宿主）

| 编号 | 判据 |
|---|---|
| A10 | 装载行生效：状态工具能取到 `listening` |
| A11 | 卸载后端口消失、连接归零 |
| A12 | 启动失败（配置错/端口占用）时宿主正常，状态里能看到原因 |

### 7.3 真实消费方（需人工）

| 编号 | 判据 |
|---|---|
| A13 | 消费方填 `http://127.0.0.1:8899` 后完成一次**可识别的新请求**（非缓存） |
| A14 | 上游停机时：**没有**到目标的连接尝试被建立（看行为，不看业务是否成功） |
| A15 | 长 SSE 正确流式转发，中途不断流 |
| A16 | 凭据不出现在：对话记录、工具输出、日志、诊断 |

> **纪律**：一次交付测试只能证明「特定版本 + 特定配置 + 该次调用路径」的行为，**不能替代持续生效的网络约束**。

## 8. 三案并陈

| 方案 | 做法 | 开发成本 | 维护成本 | 性能上限 | 扩展性 | 结论 |
|---|---|---|---|---|---|---|
| **推荐**：本地无认证转发代理（本实现） | 回环监听 + 上游注入 Basic + 分阶段隧道 | **低**（1–2 人日） | **低**（零依赖、零构建） | 单进程转发，GB/s 级富余 | 中：可加 SOCKS5 / 多上游路由 | **采用** |
| **激进**：包一层消费方网络栈 | 劫持 `globalThis.fetch` + `AsyncLocalStorage` 按 provider 路由 | 中高 | **高**（跟每个消费方版本耦合，抓取时机不可靠） | 受限于劫持点 | 高 | **否**：绑定实现细节，消费方一升级就碎 |
| **稳健**：不做代理，只做系统代理 | 让用户自己配系统代理或浏览器代理 | 极低 | 极低 | —— | 低 | **否**：解决不了「消费方只认无凭据地址」这个具体裂口 |

**复杂度量化**：技术实现复杂度 **中**。难点不在转发字节，而在**失败分阶段、粘包、以及「证明了什么」的表述纪律**。

## 10. 风险与未决
